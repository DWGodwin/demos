## Keeping them out of coding agents' way

It's a small concern, but it is one, for two reasons:

- **Stale information.** Transcripts record wrong turns along with the final decisions. This session's transcript includes my mistaken "0.13% gives 40×" claim and plans that were later replaced. An agent that searches the repo for "Foody" or "Table 5" would get hits in the transcripts mixed in with `GUIDE.md`, and could treat an old claim as current.
- **Size.** This session's transcript is about 30 KB. Over dozens of sessions they'd become the bulk of what a repo-wide search turns up.

They don't get loaded automatically. Claude Code only loads `CLAUDE.md` files on its own; transcripts enter an agent's context only if it searches or opens them.

Two small changes would handle it:

1. **A `.ignore` file at the repo root** listing `transcripts/`. Claude Code's search tools use ripgrep, which skips anything listed in `.ignore` while git still tracks it. A plain `grep -r` run in the shell would still find them, but agents mostly use the built-in search.
2. **A root `CLAUDE.md`** saying that `transcripts/` is a historical record, not to read or search unless asked, and that each project's `GUIDE.md` is the source of truth. It belongs at the root because `pizza-map-lab/CLAUDE.md` only loads when an agent is working inside that folder.

If you want to block agents from reading them entirely, a permission rule can deny reading `transcripts/`. But then they couldn't read one even when you ask, so I'd start with the two changes above.
